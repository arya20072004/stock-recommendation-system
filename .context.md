# Stock Recommendation System - Project Context

## Overview
This is a comprehensive machine learning-powered stock recommendation system that analyzes Nifty 50 stocks using technical indicators, market data, and news sentiment to provide BUY/HOLD/SELL recommendations. The system consists of a data pipeline, ML training infrastructure, web dashboard, and backtesting framework.

## Architecture Overview

### Core Components

#### 1. Data Collection Layer (`data_collector.py`)
- **Purpose**: Fetches historical stock price data for all Nifty 50 stocks
- **Data Source**: Yahoo Finance API via yfinance library
- **Storage**: MongoDB collection `historical_data`
- **Frequency**: 1-year daily data with OHLCV (Open, High, Low, Close, Volume)
- **Key Features**:
  - Handles delisted stocks gracefully
  - Prevents duplicate data insertion
  - Processes all 50 stocks in batch

#### 2. News Collection Layer (`news_collector.py`)
- **Purpose**: Gathers recent news articles for sentiment analysis
- **Data Source**: RSS feeds from Indian financial news sources (Economic Times, Moneycontrol, Business Standard)
- **Parser**: feedparser library for RSS/Atom feed parsing
- **Storage**: MongoDB collection `news_articles`
- **Key Features**:
  - Parses multiple RSS feeds for Indian financial news
  - Fuzzy matching on ticker symbols and company names
  - Stores article metadata (title, content, publication date, source)
  - Links articles to specific stock tickers
  - Prevents duplicate article insertion

#### 3. Sentiment Analysis Layer (`sentiment_analyzer.py`)
- **Purpose**: Analyzes news sentiment to enhance ML predictions
- **Technology**: FinBERT (Financial BERT) transformer model from `transformers` library
- **Process**:
  - Processes articles missing sentiment fields (label, compound, sentiment)
  - Classifies sentiment as POSITIVE, NEGATIVE, or NEUTRAL
  - Stores confidence scores alongside labels
  - Updates MongoDB with FinBERT-generated sentiment data
- **Integration**: Sentiment scores are aggregated (7-day average) and joined with price data by date for feature engineering

#### 4. Feature Engineering & ML Training (`ml_trainer.py`)
- **Purpose**: Creates ML models for each stock using historical data
- **Algorithm**: XGBoost Classifier with SMOTE oversampling
- **Target Classes**: BUY (2), HOLD (1), SELL (0)
- **Features Created**:
  - Technical Indicators: RSI(14), MACD, Bollinger Bands, ATR
  - Price Momentum: Lagged 1-day and 5-day returns (prevents data leakage)
  - Market Correlation: Rolling 30-day correlation with Nifty 50
  - Sentiment: 7-day average FinBERT sentiment score
  - Market Performance: Outperformance vs Nifty 50

- **Training Process**:
  - Labels based on future 5-day returns
  - Handles class imbalance with SMOTE
  - Time-series validation with `TimeSeriesSplit` (prevents data leakage)
  - Hyperparameter tuning with GridSearchCV
  - Proper feature lagging to avoid look-ahead bias
  - Saves models in native XGBoost format (.joblib) and feature lists (.json)

#### 5. Web Application (`app.py`)
- **Framework**: Flask with caching (15-minute cache)
- **Features**:
  - RESTful API endpoints
  - Real-time ML predictions with confidence scores
  - Interactive charts via Lightweight Charts v4
  - Modern UI with Tailwind CSS and dark theme
  - Timestamp tracking for predictions
- **Endpoints**:
  - `/`: Main dashboard
  - `/api/stocks`: List available stocks
  - `/api/stocks/<ticker>`: Stock data, prediction, confidence score, and timestamp

#### 6. Backtesting Framework (`backtester.py`)
- **Purpose**: Evaluate ML strategy performance on historical data
- **Library**: backtesting.py
- **Features**:
  - Paper trading simulation
  - Performance metrics (Sharpe ratio, max drawdown, etc.)
  - Risk analysis
  - Strategy validation

## ML Model Architecture

### Feature Engineering Pipeline
1. **Price Data Processing**: OHLCV data cleaning and validation
2. **Technical Indicators**: RSI, MACD, Bollinger Bands, ATR calculation
3. **Market Context**: Nifty 50 correlation and outperformance metrics
4. **Sentiment Integration**: News sentiment aggregation by date
5. **Momentum Features**: Multi-day return calculations
6. **Data Alignment**: Time-series alignment and missing value handling

### Model Training Process
1. **Label Creation**: Future return-based labeling (5-day horizon)
2. **Feature Selection**: Correlation analysis and importance ranking
3. **Class Balancing**: SMOTE oversampling for minority classes
4. **Hyperparameter Tuning**: Grid search for optimal XGBoost parameters
5. **Model Validation**: Cross-validation and performance metrics
6. **Model Persistence**: Joblib serialization with feature list preservation

## Key Technical Decisions

### Why XGBoost?
- Excellent handling of tabular data
- Built-in feature importance analysis
- Robust to overfitting with regularization
- Fast training and prediction
- Good performance on imbalanced datasets

### Why SMOTE?
- Addresses class imbalance in stock prediction (more HOLD/SELL than BUY)
- Synthetic sample generation preserves feature relationships
- Better than random oversampling

### Why MongoDB?
- Flexible schema for varying data types (OHLCV, news, sentiment)
- Good performance for time-series data with proper indexing
- Easy integration with Python
- Scalable for large datasets
- Supports complex queries for sentiment analysis

### Why Flask?
- Lightweight and fast for data science applications
- Easy API development with RESTful endpoints
- Good integration with ML libraries and MongoDB
- Built-in caching for performance
- Simple deployment and debugging

## Risk Management and Disclaimers

### Financial Risks
- **Not Investment Advice**: System for educational/research purposes only
- **Past Performance ≠ Future Results**: Historical analysis doesn't guarantee future performance
- **Data Limitations**: API data may have delays or inaccuracies
- **Market Volatility**: Stock markets are inherently unpredictable

### Technical Risks
- **Model Overfitting**: TimeSeriesSplit validation and regular retraining required
- **Data Quality**: Dependency on external data sources (yfinance, RSS feeds)
- **API Rate Limiting**: yfinance has usage limits; RSS feeds may be unstable
- **Model Drift**: Regular model updates needed for changing market conditions
- **Data Leakage**: Feature lagging implemented to prevent look-ahead bias
- **Sentiment Bias**: FinBERT model trained on general English, not financial-specific text
