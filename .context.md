# Stock Recommendations System - Project Context

## 📋 Project Overview

**ML-Powered Stock Recommendation System** - An advanced machine learning-based stock analysis and recommendation system for Nifty 50 stocks. The system provides intelligent BUY/HOLD/SELL recommendations using:
- Technical indicators (RSI, MACD, Bollinger Bands, ATR, CCI, ADX, Stochastic, etc.)
- Historical price data (5 years)
- News sentiment analysis using FinBERT (Financial BERT)
- XGBoost machine learning models with hyperparameter optimization
- Real-time interactive web dashboard with Flask/Jinja2
- Backtesting framework for strategy validation

**Target Market**: Indian stock market (Nifty 50)
**Database**: MongoDB (local or cloud)
**Recommendation Scope**: 50 major Indian companies

## 🎯 Core Components Overview

### 1. Data Collection Layer (`data_collector.py`)
- **Purpose**: Fetches historical stock price data for all Nifty 50 stocks
- **Data Source**: Yahoo Finance API via yfinance library
- **Storage**: MongoDB collection `stock_market_db.historical_data`
- **Frequency**: 5-year daily data with OHLCV (Open, High, Low, Close, Volume)
- **Key Features**:
  - Handles delisted stocks gracefully
  - Prevents duplicate data insertion with upsert operations
  - Batch processes all 50 stocks
  - MongoDB index: (ticker, date) unique compound index
  - ~1,250 records per stock × 50 = 62,500+ total records

### 2. News Collection Layer (`news_collector.py`)
- **Purpose**: Gathers recent news articles for sentiment analysis
- **Data Source**: NewsAPI (configurable with API key)
- **Storage**: MongoDB collection `stock_market_db.news_articles`
- **Key Features**:
  - Collects recent articles for each stock
  - Respects API rate limits
  - Stores article metadata (title, content, source, published_date)
  - Links articles to specific stock tickers via fuzzy matching

### 3. Sentiment Analysis Layer (`sentiment_analyzer.py`)
- **Purpose**: Analyzes news sentiment to enhance ML predictions
- **Technology**: FinBERT (ProsusAI/finbert) - Financial BERT transformer model
- **Process**:
  - Processes articles missing sentiment fields
  - Classifies sentiment as POSITIVE, NEGATIVE, or NEUTRAL
  - Stores sentiment label and confidence score
  - Updates MongoDB with sentiment data
- **Integration**: Sentiment scores aggregated and joined with price data for feature engineering

### 4. Feature Engineering & ML Training (`ml_trainer.py`)
- **Purpose**: Creates and trains ML models for each stock
- **Algorithm**: XGBoost Classifier with SMOTE oversampling
- **Target Classes**: BUY (1), HOLD (0), SELL (-1) → remapped to 0, 1, 2
- **Key Training Parameters**:
  - History window: 5 years (HISTORY_YEARS = 5)
  - Minimum samples: 200 rows after feature engineering (MIN_ROWS_AFTER_FEATURES)
  - Cross-validation: TimeSeriesSplit with 5 folds (N_SPLITS = 5)
  - Hyperparameter trials: Optuna with 75 trials (N_OPTUNA_TRIALS = 75)
  - Random state: 42 (for reproducibility)

- **Features Created**:
  - Technical Indicators: RSI_14, RSI_30, MACD, MACD_SIGNAL, MACD_DIFF, BB_H, BB_L, BB_M, ATR_14, CCI_20, ADX_14, STOCH_K, STOCH_D, SMA_20, SMA_50, SMA_200, EMA_12, EMA_26, MOM_10, ROC_12, CMF_20, WILLR_14
  - Price-based: Price_Change_Pct, High_Low_Ratio, Close_Open_Ratio, Volume_SMA_Ratio
  - Sector Features: Sector_Avg_RSI, Sector_Performance
  - Sentiment Features: News_Sentiment_Score, Positive_News_Count, Negative_News_Count

- **Training Process**:
  - Creates technical features for all 5 years
  - Adds sector-level information
  - Handles class imbalance with SMOTE
  - Time-series validation with TimeSeriesSplit (prevents look-ahead bias)
  - Optuna hyperparameter search with 75 trials
  - Saves models in both .joblib and .ubj formats
  - Saves feature list in JSON for inference consistency
  - Saves metrics (F1, precision, recall) in JSON

### 5. Web Application (`app.py`)
- **Framework**: Flask 3.1.3 with Flask-Caching (15-minute cache)
- **Features**:
  - Auto-loads all 50 trained models on startup
  - RESTful API endpoints for stock data and predictions
  - Real-time ML predictions with confidence tiers
  - Interactive charts via Lightweight Charts
  - Modern UI with Tailwind CSS
  - Caches predictions for 15 minutes (adjustable)
  
- **Key Functions**:
  - `load_models()` - Loads all models from /models/ into memory
  - `get_stock_recommendation(ticker)` - Generates prediction + confidence tier
  - `compute_technical_indicators(df)` - Calculates technical indicators
  - `get_display_signal()` - Maps prediction to BUY/HOLD/SELL with confidence
  
- **Routes**:
  - `GET /` or `/dashboard` - Main dashboard with stock list
  - `GET /stock/<ticker>` - Stock detail page with analysis
  - `GET /api/stock/<ticker>` - JSON API for predictions

### 6. Backtesting Framework (`backtester.py`)
- **Purpose**: Evaluate ML strategy performance on historical data
- **Library**: backtesting.py
- **Features**:
  - Paper trading simulation
  - MLStrategy class implements prediction-based buy/sell logic
  - Performance metrics (Sharpe ratio, max drawdown, win rate, total return)
  - Risk analysis and strategy validation
  - Output: MLStrategy.html interactive report

### 7. Confidence Tier System (`confidence.py`)
- **Purpose**: Assess reliability of each prediction
- **5-Tier System**: VERY_HIGH → HIGH → MEDIUM → LOW → VERY_LOW
- **Three Signals**:
  1. F1 Score (historical model quality): Threshold-based (0.42+, 0.36+, 0.30+, 0.25+, 0.00+)
  2. Max Probability (prediction certainty): Highest predicted probability across classes
  3. Top-2 Margin (class separation): Gap between 1st and 2nd highest probabilities
- **UI Logic**: Only MEDIUM+ tiers shown as actionable; LOW/VERY_LOW displayed as HOLD


## 🔄 Data Pipeline Flow

```
run_pipeline.py (Main Orchestrator)
    ├─ Step 1: data_collector.run()
    │   ├─ Fetches 5-year daily data via yfinance
    │   ├─ Processes all 50 Nifty stocks
    │   └─ Stores in MongoDB: stock_market_db.historical_data
    │
    ├─ Step 2: news_collector.run()
    │   ├─ Collects recent news articles
    │   ├─ Filters by stock ticker via fuzzy matching
    │   └─ Stores in MongoDB: stock_market_db.news_articles
    │
    ├─ Step 3: sentiment_analyzer.run()
    │   ├─ Loads unanalyzed articles
    │   ├─ Uses FinBERT for sentiment classification
    │   └─ Updates news_articles with sentiment labels
    │
    └─ Step 4: ml_trainer.run(tickers_list)
        └─ For each ticker in list:
            ├─ Load historical data + sentiment
            ├─ Create technical features (~25 features)
            ├─ Add sector features
            ├─ Optuna hyperparameter search (75 trials)
            ├─ Train XGBoost with SMOTE + TimeSeriesSplit
            ├─ Evaluate F1, precision, recall, accuracy
            ├─ Save model: model_TICKER.joblib + .ubj
            ├─ Save features: features_TICKER.json
            └─ Save metrics: TICKER_metrics.json

POST-PIPELINE DEPLOYMENT:
    flask run
    ├─ App loads all 50 models at startup
    ├─ Loads feature lists for consistency
    ├─ Serves predictions at /stock/<ticker>
    ├─ Caches results for 15 minutes
    └─ Updates live from MongoDB as needed
```

## 🤖 ML Model Details

### Feature Engineering Pipeline

**Technical Indicators** (pandas-ta library):
- RSI_14, RSI_30 - Relative Strength Index
- MACD, MACD_SIGNAL, MACD_DIFF - Moving Average Convergence Divergence
- BB_H, BB_L, BB_M - Bollinger Bands (High, Low, Middle)
- ATR_14 - Average True Range
- CCI_20 - Commodity Channel Index
- ADX_14 - Average Directional Index
- STOCH_K, STOCH_D - Stochastic Oscillator
- SMA_20, SMA_50, SMA_200 - Simple Moving Averages
- EMA_12, EMA_26 - Exponential Moving Averages
- MOM_10 - Momentum
- ROC_12 - Rate of Change
- CMF_20 - Chaikin Money Flow
- WILLR_14 - Williams %R

**Price-based Features**:
- Price_Change_Pct - % change from previous close
- High_Low_Ratio - (High - Low) / Low
- Close_Open_Ratio - (Close - Open) / Open
- Volume_SMA_Ratio - Volume / 20-day average volume

**Sector Features**:
- Sector_Avg_RSI - Average RSI of all stocks in sector
- Sector_Performance - % change of sector index

**Sentiment Features** (if available):
- News_Sentiment_Score - Aggregated sentiment from recent news
- Positive_News_Count - Count of positive articles
- Negative_News_Count - Count of negative articles

### Model Training Configuration

**Algorithm**: XGBClassifier from xgboost
**Target Classes**: 
- 1 = BUY (future 5-day return > +2%)
- 0 = HOLD (future 5-day return between -2% and +2%)
- 2 = SELL (future 5-day return < -2%)

**Hyperparameter Optimization**:
- Framework: Optuna (75 trials)
- Search space: max_depth, learning_rate, n_estimators, subsample, colsample_bytree, etc.
- Cross-validation: TimeSeriesSplit (5 folds) - maintains temporal order
- Objective: Maximize F1 (macro) score

**Class Imbalance Handling**:
- SMOTE (Synthetic Minority Over-sampling Technique)
- Integrated in imblearn.pipeline.Pipeline
- Generates synthetic samples for minority classes
- Improves recall for BUY signals

**Training Validation Metrics**:
- F1 (macro) - Primary metric for evaluation
- Precision - False positive rate
- Recall - False negative rate (BUY signal detection)
- Classification reports per class

### Model Persistence

**Serialized Formats**:
1. `.joblib` - Scikit-learn joblib format (compatible with sklearn ecosystem)
2. `.ubj` - Native XGBoost binary format (faster loading, smaller file size)
3. Feature list: `features_TICKER.json` - Ensures feature consistency during inference

## 🎯 Confidence Tier System (`confidence.py`) - Detailed

### 5-Tier Confidence Framework

Tiers (from highest to lowest confidence):
1. **VERY_HIGH** - High confidence actionable recommendation
2. **HIGH** - Good confidence actionable recommendation
3. **MEDIUM** - Moderate confidence actionable recommendation
4. **LOW** - Low confidence (suppressed, shown as HOLD)
5. **VERY_LOW** - Very low confidence (suppressed, shown as HOLD)

### Three Orthogonal Signals

**Signal 1: F1 Score (Historical Model Quality)**
- Reflects model's average performance on test data
- Calculated from 5-fold cross-validation
- Thresholds:
  - VERY_HIGH: F1 ≥ 0.42
  - HIGH: F1 ≥ 0.36
  - MEDIUM: F1 ≥ 0.30
  - LOW: F1 ≥ 0.25
  - VERY_LOW: F1 < 0.25

**Signal 2: Max Probability (Prediction Certainty)**
- Highest predicted probability from XGBoost model
- Range: [0.33, 1.0] (0.33 = random guess for 3 classes)
- Higher probability = more confident model decision
- Thresholds:
  - VERY_HIGH: Max Proba ≥ 0.75
  - HIGH: Max Proba ≥ 0.65
  - MEDIUM: Max Proba ≥ 0.50
  - LOW: Max Proba ≥ 0.40
  - VERY_LOW: Max Proba < 0.40

**Signal 3: Top-2 Margin (Class Separation)**
- Gap between 1st and 2nd highest predicted probabilities
- Large margin = clear decision boundary
- Small margin = close call between classes
- Thresholds:
  - VERY_HIGH: Margin ≥ 0.35
  - HIGH: Margin ≥ 0.25
  - MEDIUM: Margin ≥ 0.15
  - LOW: Margin ≥ 0.05
  - VERY_LOW: Margin < 0.05

### Tier Assignment Logic

- Takes minimum of three signal tiers
- Conservative approach: gates on weakest signal
- Ensures only high-quality predictions displayed as actionable

## ⚠️ Important Technical Considerations

### TimeSeriesSplit Validation
- Uses 5 folds maintaining temporal order
- Prevents look-ahead bias (critical for time-series)
- Train on past data, test on future data
- Ensures realistic performance estimates

### Feature Consistency
- Features saved in JSON during training
- Same features loaded during inference
- Prevents train-serve mismatch errors
- Both .joblib and .ubj formats supported

### SMOTE Balancing
- Addresses class imbalance in stock predictions
- More SELL/HOLD signals than BUY signals naturally
- Generates synthetic minority samples
- Applied only during training, not inference

### Confidence Tiers Implementation
- Three independent signals combined conservatively
- Only MEDIUM+ tiers shown as actionable
- LOW/VERY_LOW suppress prediction (show HOLD)
- Color-coded in UI for quick interpretation

### Caching Strategy
- 15-minute cache reduces MongoDB queries
- Automatic cache invalidation on timeout
- Manual invalidation supported
- Fallback to live data if cache miss

## 🔍 Debugging & Troubleshooting

### Common Issues & Solutions

**1. MongoDB Connection Error**
```
Error: ServerSelectionTimeoutError
Fix:
- Check MONGO_URI in .env
- Ensure mongod daemon is running
- Test connection: python -c "from pymongo import MongoClient; MongoClient('mongodb://localhost:27017/')"
```

**2. Model Loading Fails**
```
Error: FileNotFoundError for model files
Fix:
- Ensure /models/ directory has .joblib/.ubj files
- Verify /features/ has corresponding JSON files
- Check file permissions
```

**3. API Rate Limits**
```
Error: Rate limit exceeded (NewsAPI, Alpha Vantage)
Fix:
- Reduce STOCKS_TO_PROCESS in run_pipeline.py
- Add delays between requests
- Use paid API tier for higher limits
```

**4. Slow Model Training**
```
Issue: Training takes very long
Fix:
- Reduce N_OPTUNA_TRIALS from 75 to 25
- Reduce HISTORY_YEARS from 5 to 3
- Use GPU acceleration for XGBoost (set tree_method='gpu_hist')
```

**5. Low Model F1 Scores**
```
Issue: F1 scores < 0.30
Fix:
- Increase N_OPTUNA_TRIALS for better hyperparameter search
- Add more features to feature engineering
- Check data quality for gaps/duplicates
- Increase HISTORY_YEARS for more training data
- Adjust class thresholds for BUY/HOLD/SELL
```
